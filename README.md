# Qwen 文件托管与归因实验

独立的单机研究项目，入口为 `run.sh`。实验交付三份具有不同权重指纹的官方 Qwen2.5-1.5B-Instruct 副本，选择 U1 签收的模型 ZIP 作为已知来源样本，检查整个流程能否只识别 U1。

## 云主机运行

把整个目录放在 GPU 整机的数据盘，例如 `/root/autodl-tmp/qwen-file-custody`。在该目录执行：

```bash
bash run.sh
```

按目标镜像 Python 3.12、PyTorch 2.8、CUDA 12.8 设计，复用镜像自带的 PyTorch。RTX 6000D 84 GB、18 vCPU、110 GB 主存用于单卡运行。150 GB 数据盘建议启动前至少有 100 GB 可用空间，这是按 FP32 模型和临时文件估算的容量。模型、缓存、打包临时文件与结果都写入项目所在盘。首次下载需要访问 Hugging Face 权重分发服务。Tiny Shakespeare 语料随交付包提供，准备步骤核对固定 SHA-256。

## 文件流程

| 阶段 | 实现与验收 |
| --- | --- |
| 登记与密钥 | 5 名成员，各自具有身份和接收密钥，分别为发布与码本生成两组 3/5 门限密钥。 |
| 模型准备 | 固定官方权重提交，FP32 加载。训练最后五层 MLP 输出矩阵，按独立语料区间构建自然探针、校准载体并测量效用。 |
| 版本验收 | 三个独立测试码字各自的误码率 ≤ 2%，下一词预测一致率 ≥ 85%。三个预设增益均失败时停止发行。 |
| 副本发行 | 使用共享载体和 Tardos 个体码字，128 位归因、16 位共有筛查、每位 3 个探针。首次交付前承诺参数、加密托管探针。 |
| 文件交付 | 完整 FP32 副本按块 AES-GCM 加密。HPKE 绑定接收方，外层胶囊要求三个不同成员先签署意向、再批准。本人解密后签收，核对文件哈希、读回误码率 ≤ 10%、预测一致率 ≥ 85%。 |
| 筛查与归因 | 固定 U1 文件摘要后披露共有探针。至少匹配 12/16 位才披露独立归因组。成员读真实文件，在加密码本上复算并批准分数解密。按固定点修正阈值筛选副本，用签名清单映射到接收人。归因组一次性使用。 |
| 独立核验 | 独立进程加载收到的文件，依据可信摘要检查签名检查点、日志、探针披露、三个签收回执、读回与分数证明。期望最终只命中 U1。 |

## 结果与复核

每次建立新的 `runs/file.*/` 目录，保留日志、接收模型与密文。查看 `evidence/report.json` 的 `passed`、`recipients` 和独立进程输出 `verification.json` 的 `verified`。完整通过要求两个布尔值都为 true，且归因名单都是 [1]。失败保留已经生成的阶段数据。

| 文件 | 内容 |
| --- | --- |
| evidence/training.json、calibration.csv（同目录） | 训练损失、模型困惑度、各增益和测试码字的读回及效用 |
| evidence/deliveries.csv | 每份副本的批准成员、字节数、SHA-256、误码率和效用 |
| evidence/attribution.csv、trace.json（同目录） | 每份副本的分数与命中情况、裁决用整数阈值、读回和证明 |
| evidence/report.json、session.log | 主流程结果、筛查匹配、耗时、显存、设备和运行记录 |
| evidence/journal.jsonl、trust.json（同目录） | 日志与签名检查点、公钥及证书材料 |

`trust.sha256` 是可信运行结束时生成的锚点。后续交给其他人核验时，应单独通过可信渠道保留或传送。手动复核命令为 `.venv/bin/python verify.py <证据目录> --trust-sha256 <可信摘要>`。

## 论文对应与复用

文件主线对应《TVMC 中文全译》第 4.3–4.7 节，以及《TVMC 新版流程说明》的登记、发行、两阶段批准、先筛查后归因与门限评分步骤。第一版聚焦完整文件样本。100 副本、2048 位、合谋与变换鲁棒性、API 申辩及 L3 飞地留待单独实验。

模型下载、文件实验编排、独立核验与一键入口为本项目设计。`tvmc/` 中密码、证书、日志、流式交付、门限追踪和载体运算来自 ZhouJay798/TVMC_demo 的提交 4bf5995，已在本目录保存文件路径所需的实现。各角色共用进程和机器，密码部分使用研究实现和模拟身份，未实现物理隔离或可证明的安全擦除。归因结果指向副本来源。
